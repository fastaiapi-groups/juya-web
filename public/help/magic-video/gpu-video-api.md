# GPU 视频接口与模型参数

业务链路统一为 **调用方 → NewAPI → Go Wrapper → 显卡**。Go 负责持久化队列、资源池隔离、显卡分配、JPEG 转码、断线恢复和结果保存。云平台账号、GPU 服务地址和工作流图留在服务端。

## 公共字段

| 字段 | 含义 |
| --- | --- |
| `model` | 公开模型 ID，必填 |
| `prompt` | 非空提示词 |
| `seconds` | 输出时长；模型范围见下表，不与 `duration` 同时传入不同值 |
| `size` | `宽x高`，建议明确提供，并按所选模型对齐 |
| `input_reference` | 首帧 URL，或 multipart 文件；不等于人物参考图 |
| `metadata.channel` | `autodl`、`autodl-native` 或 `xiangongyun` |
| `metadata.last_frame_url` | 尾帧，模型支持时提供 |
| `metadata.reference_images` | 有序人物、场景、道具参考图数组 |
| `metadata.reference_audios` | 有序音频数组，模型支持时提供 |
| `metadata.reference_videos` | 有序参考视频数组，模型支持时提供 |
| `metadata.resource_account_key` | 可选的用户资源池 Key，省略时使用平台资源池 |

相同字段在顶层和 metadata 中冲突时拒绝。时长、素材数量、分辨率按最终转发参数校验。不要传 `node:field`、工作流 ID 或云账号 Token 作为视频参数。

## AutoDL 面板模式（6008）

以下为当前适配器的请求范围。镜像还必须具备对应模型文件；已实现适配器与实际镜像验收分别记录。

| 模型 | 模式 | 时长 | FPS | 素材 |
| --- | --- | --- | --- | --- |
| `minimax-h3` | 文生、首帧、首尾帧、参考 | 5–15 整数秒 | 24 | 参考模式最多 9 图、3 音频；不支持参考视频 |
| `minimax-h3` + `metadata.variant=fast` | 加速文生 | 5–15 整数秒 | 24 | 不接受首帧或参考素材 |
| `minimax-h3-u24` | 文生、参考 | 5–15 整数秒 | 24 | 最多 9 图、3 音频 |
| `minimax-h3-u32` | 文生、参考 | 5–15 整数秒 | 24 | 最多 9 图，不接受音频或视频 |
| `minimax-h3-u17` | 文生 | 5–15 整数秒 | 24 | 不接受参考素材；Linux 使用普通缩放导出 |
| `wan2.1` | 文生 | 1–15 整数秒 | 8–60，默认 16 | 不接受参考素材，不生成音轨 |
| `wan2.2` | 首帧 | 1–15 整数秒 | 16 | 必填一张首帧；不生成音轨 |
| `ltx-2.3` | 首帧 | 1–15 整数秒 | 8–60，默认 30 | 必填一张首帧，原生音画 |
| `ltx-2.3-grid` | 四宫格 | 4–15 整数秒 | 24 | 必填一张 2×2 四宫格图，依次使用左上、右上、左下、右下 |
| `ltx-2.3-avatar` | 数字人 | 5–15 整数秒 | 30 | 一张人物图与一段足够长的完整配音；可使用 1–8 段动作脚本 |

H3 / LTX 自定义尺寸按 32 对齐，单边 256–1920，最多 1920×1088 像素。H3 常用尺寸：864×480、1376×768、1920×1088，竖屏交换宽高。U32 和 U24 不以首帧参数代替普通参考图。

Wan 2.2 按首帧原比例确定宽高，使用长边档位 `480/768/1024/1280/1536`；不要把长边档位当作固定宽高。视频中的实际尺寸会据此对齐到 16。选择 480 档不保证得到 480×288。

NewAPI 的 H3 分辨率计费标签为 `480p/768p/1080p`；1080p 对应按模型对齐的 1088 像素短边。若同时给出尺寸与标签，插件要求二者相符；只给标签时生成明确尺寸。只给尺寸时从实际短边推导档位，不再默认把所有尺寸按 480p 处理。售价仍使用管理员已保存的配置。

## 原生 ComfyUI 与仙宫云

`autodl-native` 连接原生服务端口 6006，能力目录与面板不同；例如 Wan 2.1 使用原生工作流。AutoDL 面板资源池也可通过同一面板的 Comfy 代理执行 Wan 2.1 原生图，使用 `metadata.channel=autodl`，与 H3/LTX 共用一张卡的队列和锁；无需另建竞争资源池。不能把 6008 的路径、模板 ID 或 LTX 参数复制给 6006。一个实例只由一个资源池调度，避免不同资源池同时占用同一张卡。

仙宫云使用 `minimax-h3-x`、`ltx-2.3-x`，`metadata.channel=xiangongyun`。H3-X 支持已适配的首尾帧、多参考图、参考视频、音频与 Hybrid 组合；LTX-X 使用自己的首尾帧工作流。不能据 AutoDL 的同名家族推导仙宫云参数，或反向套用。完整能力以资源池返回的 `/v1/channel-models` 为准；该接口供拥有相应服务端凭据的管理端使用。

## 结果与恢复

保存创建响应的 NewAPI `task_…`，之后查询同一 NewAPI 的 `/v1/videos/{id}`；完成后通过 `/v1/videos/{id}/content` 下载。公开响应的内容地址使用当前网关任务 ID，不把私有显卡 URL 当作下游下载地址。

创建超时不能证明任务未被接收。Go 保留提交回执不确定的任务并查询原显卡队列与历史，不自动重复 POST。明确失败后才重新创建；升级服务使用持久化任务与原上游 ID 恢复跟踪。

接口接入文件见 [NewAPI 插件下载与安装说明](https://fastaiapi.cloud/help/magic-video/#plugins)。真实验收报告以任务 ID、下载状态与成片探测数据为证据，不能仅用 HTTP 受理成功判定模型已跑通。
